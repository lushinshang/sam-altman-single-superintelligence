49:38 它不是 AI 的標準單位。然而，我們卻走到了這一步。你知道，我們確實討論過——你可能會說用成果，但我不認為能用成果。因為不同使用情境之間的成果差異太大了。什麼才是合適的標準化單位？我們差點做出一個非常——其實會是很糟的決定，說我們下一個模型完全不以 token 計價。而你只要給它一段提示詞。然後我們就會報一個價格給你。接著我們就把它執行完畢。對你來說它就像 AWS 一樣。只要做點事情，我們就寄帳單給你。

50:09 但客戶對此的反應非常負面。他們就像在說：「我得以某種方式知道我在付什麼錢。」是的。而且，我問過幾個人：「你寧可為相同的產出支付更多費用，但以某個一致的 token 數量來計價嗎？或是之類的？」即使我們把 token 數量灌水，他們也說：「噢，我寧可你們把 token 數量灌水、讓我多付錢。因為我知道背後有一個真實存在的東西。」所以我認為你說得對，大家不想只讓我們給他們一個價格，因為他們覺得長期下來自己不知怎地會被坑。

50:40 就像大家可能寧願付 CPU 時數的錢，也不願只把事情辦好，即使那樣其實比較便宜。你知道那種方式，奈米……晶片閘極長度？那完全是虛構的。沒錯。如今奈米與現實幾乎毫無關聯。我們在 token 上也會遇到類似的情況嗎？你們是不是該開始說：「這是一個等效智慧 token」，就像 I Can't Believe It's Not Butter 那樣。指的是最小特徵尺寸？是啊。我……那根本是編造出來的。我希望不會。

51:10 我是說，用奈米這個詞來稱呼跟奈米毫無關係的東西，讓我很受不了。我知道，這非常愚蠢。是啊。所以……你不會喜歡那樣的。我寧可不要編造一個虛構的單位。token 也算是一種虛構的單位。我是說，它們在某種意義上是真實的，但並不是個好的單位。從商業價值的角度來看，它們是虛假的。但難道唯一的……好。替 token 辯護的唯一理由，不就是如果你在浪費 token，我們應該儘快修正這個問題嗎？我們不該串流傳輸——克勞德・夏農絕不會贊同我們只串流雜訊而非訊號。

51:42 因此，將會有一個……在兩端都會有一個資訊理論上最有用 token 的下限。我們大概會回到那個水準。沒錯。我的意思是，現在你必須思考到底該選擇小模型每百萬 token 10 美分的 token，還是大模型每個 token 10 美元的 token。然後還要考慮……思維鏈（chain of thought）可能會有多長。而那純粹是認知負擔，我認為實際上沒有增加任何價值。思維鏈有包含在內嗎？
